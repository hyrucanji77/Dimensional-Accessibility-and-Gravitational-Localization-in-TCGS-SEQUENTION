# Reproducing computational release 4 for manuscript v4.2 Final

Henry Arellano-Peña. *Dimensional Accessibility and Gravitational Localization: Spectral Response, Boundary Stability, and Constitutive Constraints in TCGS-SEQUENTION*. 29 October 2026.

## Scope and provenance

This dedicated repository contains the three programs and two test files from the complete computational release originally published in `hyrucanji77/TCGS-SEQUENTION-protocol` at commit `1353cf54a94cfb6f3923a1f2a9c467d9eff68afa`. Their bytes, mathematical inputs, and checks are preserved. The original immutable citation in manuscript version 4 remains valid; the present repository provides a standalone home with paper-specific documentation and result records.

The programs evaluate a conditional static scalar half-line response. They do not fit observations, establish Counterspace empirically, or provide a relativistic tensor completion.

## Compatibility with the final manuscript

The current article is **v4.2 Final: 45 pages and 29 numbered references**. It retains the version 4 programs, tests, inputs, and numerical outputs without modification. Its reference [18] identifies both the dedicated snapshot `d8c5ade46c0c47ceaa2408f7965ae58402e5b479` and the original protocol snapshot `1353cf54a94cfb6f3923a1f2a9c467d9eff68afa`. Metadata at those historical commits describe the original 41-page, 27-reference manuscript and are not rewritten.

**Appendix F.4, including Proposition F.1 and Equations (89)–(95), is analytical and is not part of the 529 numerical checks.** The spatial-dilation selection, variational argument, conformal property, and source-scaling discussion are established in the manuscript. No additional computational coverage or new test run is claimed by this documentation-only update.

`CITATION.cff` retains software version `4`; `release.json` separately identifies the current manuscript and the original release-associated article. The unchanged scientific checksum manifest remains applicable. See [MANUSCRIPT_COMPATIBILITY.md](MANUSCRIPT_COMPATIBILITY.md).

## Environment

The release was rerun using Python 3.13.5, NumPy 2.3.5, SciPy 1.17.0, and mpmath 1.3.0. The requirements files pin those dependency versions. Use the verified Python version when reproducing the archived environment; the scripts' older minimum-version comments do not guarantee that every pinned dependency supports every older interpreter.

From the repository root:

```sh
python -m pip install -r requirements.txt
python code/reproduce.py --output results/dimensional_accessibility
python code/verify_extensions.py --output results/dimensional_accessibility
python code/verify_geometry_constraints.py --output results/dimensional_accessibility
python -m unittest discover -s tests -v
```

No network access or external dataset is required after installation. The published coefficients are documented numerical inputs. The programs do not download or infer experimental likelihoods.

## Output files

`reproduce.py` performs **186 numerical checks** and produces **12 table rows**. It writes `response_table.csv` and the full per-check report `verification.json`. The unchanged program also generates an optional local table-formatting file; generated TeX files are ignored and are not tracked in this repository.

`verify_extensions.py` performs **225 numerical checks** and writes `extension_verification.json`. These checks cover the warped-action reduction, the three-in-four candidate, positive-measure finite differences, Laplace/resolvent integrability, detuned resonance poles, threshold ratios, and the AQUAL flux Jacobian.

`verify_geometry_constraints.py` performs **118 numerical checks** and writes `geometry_constraint_verification.json`, `published_powerlaw_limits.json`, and `cross_sector_hierarchy.json`. These outputs document the geometry, localization threshold, force/potential conversion, historical coefficient provenance, and conditional comparison between the laboratory radius and an illustrative AQUAL scale.

The repository tracks the numerical table, published-coefficient record, hierarchy calculation, execution summary, and software-test log. **The three full per-check JSON reports are regenerated by the commands above**, rather than required as inputs. They record individual values and tolerances. With no `--output` option, the scripts write to `results/` relative to the repository root.

There are **529 numerical checks** and **nine separate unit tests**. Unit tests are not counted in the 529. All passed in the verified run. The regenerated table and numerical JSON reports matched the version-4 article package byte-for-byte in that environment. Across other platforms, comparisons should use the recorded tolerances rather than an assumption of bitwise identity.

Finite checks are not proof certification, verification of every member of an infinite inequality hierarchy, or empirical evidence for a framework interpretation.

## Published inputs

`published_powerlaw_limits.json` distinguishes the original experimental attribution from the table supplying a coefficient and its confidence convention. Hoskins et al.'s earlier k=2 limit is recorded from Adelberger et al. Table I and corroborated by Hoyle et al. Table XIV. Hoyle's own weaker k=2 value remains a separate comparison. The adopted 2007 coefficient retains the table's **68% convention**. No new 95% claim or strongest-current-bound claim is made.

The acceleration in `cross_sector_hierarchy.json` is the illustrative central 2016 radial-acceleration calibration, not a newly fitted AQUAL scale. Its uncertainty is not combined with the laboratory constraint. The hierarchy assumes identification of the same curvature with the scale-setting functional.

## Integrity and citation

The three original script SHA-256 values are recorded in `results/dimensional_accessibility/summary.json`. `SHA256SUMS.txt` covers the scientific scripts, tests, dependency pins, scoped code license, and distributed result records. It does not cover repository-specific prose or itself. On systems with the utility installed:

```sh
sha256sum -c SHA256SUMS.txt
git rev-parse HEAD
```

The second command identifies the immutable revision to cite. `release.json` records the original upstream provenance; `CITATION.cff` supplies citation metadata. No unrelated files in the original protocol repository are changed by this dedicated release.
